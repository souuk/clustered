TEENSY STM FOUR-PANEL PLOTTER
================================

WHAT TO USE AS INPUT
--------------------
Each scan requires all three matching files from the data folder:

  <prefix>F<number>.hex   forward binary samples
  <prefix>B<number>.hex   backward binary samples
  <prefix>P<number>.txt   dimensions and scan settings

For example, the supplied STM12 scan with prefix STM and number 1 uses:

  data\STMF1.hex
  data\STMB1.hex
  data\STMP1.txt

The .hex files are raw binary signed 16-bit integers, not hexadecimal text.
The P file is ordinary text. Do not convert the .hex files to .txt before
plotting.

WHAT EACH BINARY VALUE MEANS
----------------------------
The firmware casts PID Output to int16_t and stores it while sending the same
controller correction to the Z DAC. Therefore every plotted value is Q, a
signed PID-output count. It is not a raw ADC-current sample and cannot be
labeled as height without a measured piezo calibration.

OPTIONAL SYNTHETIC FORMAT DEMONSTRATION
---------------------------------------
To test the pipeline without presenting experimental data, generate a separate,
unmistakably labeled format demonstration with:

  python -m tunnelpy.generate_synthetic_scan

This creates synthetic_data\SYNF1.hex, SYNB1.hex, and SYNP1.txt plus the
schema-check, raw-data-to-matrix, and four-panel figures. The generator models
scanner tilt, slow line drift, first-order feedback lag in each acquisition
direction, signed output limits, noise, and a known triangular corrugation. It
is not experimental evidence, proof of tunneling, or calibrated surface
height.

FIRST: INSPECT THE AVAILABLE DATA
---------------------------------
From the "cosmos presentation" directory:

  python -m tunnelpy.inspect_scans data --output tunnelpy\scan_inventory.txt

VALIDATE THE SUPPLIED SCAN
--------------------------
The supplied STMF1 file contains 4,088 of the requested 4,096 samples, while
STMB1 contains all 4,096. STMP1 reports completion, so the parameter record and
binary length disagree. Create the archived quality report with:

  python -m tunnelpy.validate_scan data --output results\reference-scan-1\validation.txt

PLOT WITH MASKED RECONSTRUCTION
-------------------------------
The newer partial-data method keeps the requested 64 x 64 matrix, retains all
4,088 valid forward samples, and marks only the eight missing values as
unknown. It does not interpolate or invent measurements:

  python -m tunnelpy.plot_stm data --allow-partial --output results\reference-scan-1\four-panel-raw.png

The default image is:

  results\reference-scan-1\four-panel-raw.png

Missing samples are pale red. The mean and difference panels remain masked
where either direction is missing. Use --partial-mode rows only to reproduce
the older behavior that discards every incomplete row.

FOR A FUTURE COMPLETE SCAN
--------------------------
If the files contain exactly points × lines samples:

  python -m tunnelpy.plot_stm data --prefix STM --scan-number 2

FOUR PANELS
-----------
1. Forward scan: values acquired while X moves forward.
2. Backward scan (spatially aligned): each backward row is reversed so the
   same X location appears in the same column as the forward scan.
3. Forward/backward average: emphasizes repeatable structure.
4. Forward minus backward: exposes drift, hysteresis, line offsets, noise, and
   disagreement between directions.

All panels use grayscale so the figures remain legible when printed in black
and white. In the difference panel, negative values are light, zero is
mid-gray, and positive values are dark.

OPTIONS
-------
  --level none    preserve raw counts (default)
  --level mean    subtract the overall mean
  --level line    subtract each row's median
  --level plane   subtract a least-squares background plane
  --full-range    use extrema instead of robust percentile color limits
  --dpi 300       create a higher-resolution image for printing
  --show          open the Matplotlib window after rendering

APPENDED FILE WARNING
---------------------
The firmware uses append mode. Some supplied filenames contain several scans.
The program rejects these by default because the binary files contain no
reliable separators. If external evidence identifies the wanted record, select
the matching parameter record and explicitly choose the start or end:

  --parameter-record 0 --segment start
  --parameter-record -1 --segment end

Do not treat this selection as verified merely because it produces a picture.

BATCH MODE
----------
This attempts every parameter-file set and skips unsafe or unusable inputs:

  python -m tunnelpy.plot_all_scans data --allow-partial

SOURCE CONTRACT
---------------
The reader follows the newer firmware in source.zip:

  Experiments\STM Project\Teensy_STM12_July_29_2026_v1.ino

That source writes signed two-byte values to the F/B files and text settings to
the P file. It also uses file append mode, which is why oversized scans are not
silently accepted.

KNOWN Z-CALIBRATION PROBLEM
---------------------------
The firmware stores the PID output count Q directly. It does not define or
subtract a Q_ref, and it does not contain a measured conversion from controller
counts to nanometers or angstroms.

The source provides only an electrical DAC conversion:

  32767 counts = +14.376 V
  alpha_V = 14.376 / 32767 = 0.000438734 V/count

There is a minor inconsistency because the default-bias comment uses 14.356 V
instead of 14.376 V. This should be verified experimentally.

Two reference counts appear in the source:

  Q_ref = 0       electrical zero volts
  Q_ref = 32767   fully retracted Z command

Neither is automatically subtracted from the saved scan. A physical conversion
would require:

  delta_z = alpha_z * (Q - Q_ref)
  alpha_z = alpha_V * Z-amplifier gain * piezo displacement sensitivity

The Z-amplifier gain and piezo displacement sensitivity are not defined in the
Teensy source. Until they are measured and their sign is verified, all plots
must remain labeled as controller counts rather than physical height.
